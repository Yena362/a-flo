# 에이플로 (A-Flo)

> 교수님 스타일까지 읽고, 제출 전에 예상 학점과 감점 포인트를 짚어 주는 AI 과제 코치
>
> 과제 맞춤형 AI 채점 및 학점 방어 솔루션 · 팀 A-Flo

> 🧪 **지금 보고 있는 곳은 `demo` 브랜치예요.** 채점 엔진이 실제로 동작하는 걸 보여 주는 **임시 화면**이 들어 있어요.
> 최종 화면은 화면 담당자가 만들고, 이 브랜치는 참고용이라 `main`에 합치지 않아요.
> 실행: `npm start` → 브라우저에서 http://localhost:8080 → 과제 검사 → "예시 과제 불러오기" → 분석 시작
> AI 채점은 Vercel에 배포한 주소에서만 동작해요([docs/AI.md](docs/AI.md)). 내 컴퓨터에서는 "기본 채점"으로 표시돼요.

## 이 저장소에 뭐가 들어 있나요? (비전공자용 설명)

앱을 식당에 비유하면 이렇게 나뉘어요.

| 부분 | 식당으로 치면 | 하는 일 | 담당 |
|---|---|---|---|
| **채점 엔진** | 주방 | 과제 글을 읽고 점수·학점·감점 이유·수정안을 계산 | 개발 |
| **화면** | 홀·메뉴판 | 사용자가 보고 누르는 부분 (홈, 퀴즈, 결과, 에디터) | 화면 개발 |
| **디자인** | 인테리어 | 색, 캐릭터 그림, 아이콘 (PNG로 전달) | 디자인 |

- **`main` 브랜치(지금 보고 있는 곳)**: 채점 엔진과 데이터(퀴즈 문제, 캐릭터, 저장 기능)가 있어요.
- **`demo` 브랜치**: 엔진이 실제로 어떻게 동작하는지 보여 주는 **임시 화면**이 있어요. 화면 담당자가 참고용으로 보면 돼요. 최종 화면은 화면 담당자가 만들어요.

> **브랜치란?** 같은 프로젝트의 "평행 우주 복사본"이에요. 각자 자기 브랜치에서 작업하고, 다 되면 `main`으로 합쳐요(Pull Request).

## 폴더 안내

```
js/
  analyzer.js    ← 규칙 채점 엔진 (형식: APA, 분량, 출처, 구어체…)
  ai.js          ← 규칙 + Gemini AI 채점을 합쳐서 돌려주기 (화면에서 부르는 함수)
  ai-prompt.js   ← Gemini에게 주는 채점 지시문
  ai-merge.js    ← 규칙 점수와 AI 점수를 합치는 방법
  docx.js        ← 업로드 파일 읽기: 한글(HWP·HWPX)·PDF·워드(DOCX)·TXT
  hwp.js         ← 한글(.hwp) 파일 해석 (라이브러리 없이)
  quiz-bank.js   ← 1분 퀴즈 문제 은행 (과제 모드 10문제 + 시험 모드 10문제)
  store.js       ← 연속 학습(불꽃), 검사권, 검사 기록 저장
  mascot.js      ← 캐릭터 4종(삐약이·학점이·불씨·에이) 그림과 표정
  sample.js      ← 시연용 예시 과제 (일부러 틀린 곳을 넣어 둠)
api/analyze.js   ← Vercel 서버 함수 (Gemini API 키를 숨겨 두는 곳)
assets/mascot/   ← 디자인팀 PNG를 넣는 곳 (넣는 법은 그 폴더의 README)
docs/
  ENGINE.md      ← 화면 담당자용: 엔진 사용법
  AI.md          ← Gemini 키 받기 → Vercel 배포 → 화면 연결 (비전공자용)
  PLAN.md        ← 무료/프리미엄 요금제, 유료 출시 전 할 일
  ROLES.md       ← 누가 무엇을 하는지, GitHub 작업 순서
tests/           ← 엔진이 제대로 계산하는지 자동으로 확인하는 시험지
```

## 채점 엔진이 지금 잡아내는 것

기획안 "STEP 1 입력 → STEP 4 결과 → STEP 5 교정" 흐름 기준이에요.

| 확인 항목 | 예시 | 자동 수정안 |
|---|---|---|
| 참고문헌 APA 7판 형식 | `서울: 박영사` 같은 출판사 위치, 『』 표기, 연도 괄호 | 있음 |
| 출처 없는 직접 인용 | 따옴표 문장 뒤에 (저자, 연도) 없음 | 있음 (자리 표시) |
| 근거 없는 수치 | "100%를 넘는다" 같은 통계에 출처 없음 | 있음 (자리 표시) |
| 구어체·존댓말 어미 | 진짜, 완전, ~해요, ~거든요 | 있음 |
| AI 문체 의심 표현 | "다양한 측면에서", "중요한 역할을 한다" | 제안만 |
| 너무 긴 문장 | 140자 넘는 문장 | 제안만 |
| 서론-본론-결론 구성 | 교수님 태그 "서론-본론-결론파" | 제안만 |
| 수업 중 구두 지시사항 | "서론에 뉴스 기사 인용할 것" | 제안만 |
| 분량 | "2,000자 이상" 같은 말씀에서 자동으로 찾음 | 제안만 |

결과로 **예상 점수(100점), 유력 학점(A+~F), 루브릭 4항목 점수, AI·표절 의심률(안전/주의/위험), "이것만 고치면 ○○ 가능!"** 을 돌려줘요.

> 규칙 엔진은 **형식**을, Gemini AI는 **내용**(주제 부합·논리·지시사항 충족)을 평가하고 둘을 합쳐 점수를 내요. AI 연결 방법은 [docs/AI.md](docs/AI.md). AI·표절 의심률은 실제 표절 검사기가 아닌 **예상치**예요.

## 직접 돌려 보기

필요한 것: [Node.js](https://nodejs.org) 18 이상 (설치 외에 추가 패키지 없음)

```bash
# 엔진 시험 (모두 ok가 나오면 정상)
npm test

# 임시 화면 보기 (demo 브랜치에서)
git switch demo
npm start          # 그다음 브라우저에서 http://localhost:8080 열기
```

## 팀 작업 규칙 요약

1. `main`에 직접 올리지 않기 → 내 브랜치 만들기 → Pull Request → 다른 사람이 확인 후 합치기
2. 할 일은 GitHub **Issues**에 적고 담당자 지정
3. 엔진을 고치면 `npm test`가 통과하는지 확인

자세한 내용은 [docs/ROLES.md](docs/ROLES.md)를 보세요.
